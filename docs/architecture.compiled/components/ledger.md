# Ledger

## Purpose & Boundaries
Context `ledger` (Go only, database `passage_ledger`; waves 11-15, 38, 40). Universal journal; FX, tax, close, statements, budgets, cost ledger, consolidation. `ledger.Post` (`POST /v1/ledger/journal-entries:post`) is the ONLY synchronous cross-context write. Owns period control (taken from platform per Q1). Posts as a service principal, not the end user. SLO 99.95%, >=3 replicas across zones, 3-instance CNPG synchronous replication, PDB.

## Interfaces
- `POST /v1/ledger/journal-entries:post` (Svc:`journalentry.post` + subject token | User). Request: legalEntityId, postingDate, documentDate, source{context, documentType, documentId, documentNumber, purpose}, currency, rateType, lines[{lineNo, account, dimensions, debit|credit Money, taxCode, sourceLineId}], autoReverseOn. Headers: Authorization, `X-Passage-Subject-Token`, `Idempotency-Key`, traceparent, `X-Correlation-Id`. `201`: journalEntryId, documentNumber (gap-free `{LE}-GJ-{FY}-{#######}`), postedAt, postingDate, per-ledger lines with transactionAmount/accountingAmount/reportingAmount + rate id/version, roundingLines, `ETag: "v1"`; replay returns stored response with `Idempotent-Replayed: true`.
- Rules/errors: `422 unbalanced_entry`, `422 period_closed` (checked INSIDE tx with `FOR SHARE` on period_control row; `:close` takes exclusive lock), `422 dimension_invalid` (errors[] names line+dimension), `422 validation_failed`, `409 unique_violation` (unique (tenant, source.context, documentType, documentId, purpose) and (tenant, idempotency_key)); rate override needs `journalentry.rateoverride` + reason; parallel ledgers fan out; rounding once at document level with explicit rounding lines.
- Also: `journal-entries:validate|:batch`, `GET /posting-requests/{key}` (posted+journalEntryId+glSeq | in_progress | 404; used by inventory sweeper), `journal-entries/{id}` (+`/lines`, `:reverse`), `journal-lines`, `journal-batches` (JB- number; submit/post/reject/import), `balances`, `trial-balance`, `balances:rebuild`, `exchange-rates:lookup|:fetch`, `revaluations`, `translations`, `tax:determine|:calculate` (read-like), `tax-settlements` (+`:post`), `statutory-reports/{type}:generate`, `period-controls` (`:close|:reopen|:hold|:check`), `close-checklists`, `year-end-closes`, allocation/accrual runs, `statements:run`, `statement-runs/{id}/cells/{cellId}/lines`, `reconciliations`, `budget-checks`, `budgets/{id}:activate`, `encumbrances`, `cost-allocations:run`, `consolidations`, `intercompany-pairs`, `GET /v1/ledger/reconciliation/{check}?le=&fy=&glSeq=`.
- Caller protocol (kernel `ledgerclient`): key `post:<context>:<documentType>:<documentId>:<purpose>[:<revision>]` (<=128 chars, never random/time-based); post-then-finalize (no caller tx open across call); sync path timeout 3 s, up to 3 retries same key, then `503 upstream_unavailable`; bulkhead per service principal, `429/503` + `Retry-After`.
- Authz: OPA allows `journalentry.post` only for `data.passage.posting_sources[service]`; ledger records `postedBy=user:<sub>`, `postedVia=service:<name>`; system posts use `actor=system:<job>`; no RFC 8693 exchange on hot path.

## Data Ownership
EN-023..036 + 9.8. `journal_entry` and `journal_line` (append-only, monthly range partitions on `posting_date`, PK (tenant_id, posting_date, id)); entry cols include document_number, fiscal_year, gl_seq (gap-free counter value, scoped tenant x LE x FY), entry_type standard|reversal|closing|opening|revaluation|allocation|accrual|elimination|adjustment|migration_opening, source_context/source_document_*, reverses_id+reverses_posting_date, intercompany_pair_id, idempotency_key, lines_digest. Lines: signed amounts amount_txn/amount_acc/amount_rpt (debit>0, credit<0), rate_txn_acc, rate_acc_rpt, rate_type, rate_date, line_kind normal|tax|rounding|revaluation|allocation|elimination|opening|accrual, dimension_hash. `posting_request` (PK (tenant_id, idempotency_key); UQ document_number; UQ journal_entry_id), `balance` (yearly partition on fiscal_year; upserted SYNCHRONOUSLY in posting tx), `balance_by_currency`, `balance_watermark`, `dimension_set`, account, account_structure(+rule), dimension(+value), ledger (one leading per LE; kind leading|parallel), rate_type, exchange_rate, posting_profile(+account), period_control (module all|gl|ap|ar|inventory|assets|cash|production|projects|tax|bank|payroll; status open|on_hold|closed|permanently_closed), tax_*, tax_transaction, journal_batch, allocation, accrual, close_checklist, statement_definition, budget, cost_ledger_entry, consolidation_*, tax_settlement, intercompany_pair. Immutability trigger: UPDATE/DELETE rejected on posted rows except settled_amount, settlement_status, printed_at, journal_entry_id, gl_posting_status (+version, updated_at, updated_by).

## Events Produced
`ledger.journalentry.posted.v1` (48 partitions; >~1,500 lines carries header+totals+`linesUrl`; first 200 lines inline), `ledger.journalentry.reversed.v1` (subject = original entry), `ledger.exchangerate.published.v1` (+snapshot), `ledger.period.closed.v1`, `ledger.periodcontrol.changed.v1` (+snapshot; producer is ledger), `ledger.taxsettlement.posted.v1`, `ledger.intercompanypair.matched|mismatched.v1`, `ledger.reconciliation.completed.v1` (emitted by platform-ts).

## Events Consumed
`ledger-budgetcontrol` (journalentry.posted, purchaseorder.confirmed, vendorinvoice.posted), `ledger-intercompany` (journalentry.posted with intercompanyPairId; G order), `ledger-reconciliation*` (tie projection only, NOT a posting trigger), `ledger-closechecklist` (reconciliation.completed), `ledger-statutory` (taxsettlement.posted), `ledger-bank`, `ledger-partymerge`, `ledger-legalentity-ref`, `ledger-approvals`, `ledger-numbersequence`. (`procurement|sales|inventory|treasury-reversal` consumers link subledger docs to `journalentry.reversed`.)

## Dependencies
internal: platform (calendars, legal entities), edge-identity, platform-kernel (sequence, ledgerclient). external: FX providers (ECB et al.; last-known rate with warning, block only if no rate for date), tax providers (Avalara/Vertex; internal fallback else 503).

## Gotchas & Constraints
- Group-commit micro-batching (<=5 ms or 200 entries) reserves contiguous number range; wave-11 k6 benchmark gate decides shipping; deferred constraint trigger may be replaced by engine check + 02:00 `reconcile-daily` (R-02). Number allocated LAST in the tx; rolled-back post never consumes a number. Gap-free GJ ~2,000 allocations/s per sequence (R-04).
- NFR-P1: 5,000 lines/s sustained, p99 < 200 ms. Topic `passage.ledger.journalentry` 48 partitions keyed `tenantid:subject`.
- Ledger never trusts a cache for period checks; non-ledger services keep advisory 5 s pre-check.
- Closed-period contract test must pass on EVERY posting path (reversal, migration, batch).
- Balance rebuild: shadow tables, catch-up by gl_seq, verify, swap; compare-only nightly (NFR-D2); needs `RebuildProjections` duty + controller approval for closed years.
- Reversal lines are exact negation; closed-year opening entries must be excluded from the reconciliation movement term (R4-1 open).
- Immutable: corrections only via `:reverse` or new entries.
