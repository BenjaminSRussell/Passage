# Migration module

Web screens for `services/migration` (wave 10): migration runs (list, start from a published mapping spec, detail with exception queue, warnings, reconciliation and re-run of rejects), mapping specs (list, publish from pasted JSON, detail) configuration packages (list, paste package and signature, preview the diff, apply, detail with applied history) connections to the source ERP (list with kind and status filters, create, detail with editable settings, a write-only secret field and a Test button that shows the probe result) entity bindings (which table, query, endpoint or file of a connection feeds which entity: list with connection and status filters, create with a preview of the mapped records and rule errors before saving, detail with an editable source and a preview, optionally from a file chosen in the browser) delta sync (the run monitor: every scheduled binding with its state, last success, next due time, failures, watermark and conflicts; the detail page pauses and resumes the schedule, makes it due now, sets the source of truth, lists recent runs, the rejects of the last run and the conflicts, and resolves each by keeping Passage or accepting the legacy values) and migration projects (list with type and status filters, create, detail with archive or reactivate, an edit form for the name, cutover and schedule of an active project and, for copy projects, the ordered key rewrite rules with a preview on sample keys).

The API client sends `Idempotency-Key` on commands. `migration.run`, `migration.spec.write`, `migration.package.apply`, `migration.project.write` and `migration.connection.write` are enforced by the service; the routes and buttons are also gated on them. The Connections, Entity bindings and Delta sync nav items are gated on `migration.run` (seeded); the other nav items carry no duty because their duties are not seeded in `policies/authz/data.json` yet (see `services/migration/NOT-IMPLEMENTED.md`).

Connections never hold or show a secret: the create form has only settings, the secret field on the detail page is a password input that is cleared after every attempt, and the page shows only whether a secret is set and when. Source systems can be `custom_<name>` (the project form and the connection form both offer "Custom system").
