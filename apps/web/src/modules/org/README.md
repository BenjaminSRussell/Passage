# org web module

Organization workspace for wave 6: legal-entity switcher (`passage.org.legalEntity`), Legal entities screen and legal-entity-scoped operating unit, site and warehouse lists. Discovered by the shell via `module.ts`.

Routes: `/org/reference-data` (nav "Reference data", duty `org.read`) holds the Reference data screen: countries, currencies, regions, languages, units and conversions, one tab loaded at a time. Deactivate, add custom unit and add conversion render only when `OrgLayout` receives `org.reference.write` in `duties`; the Test conversion panel needs no write duty.

Tenant-level fetch rule: reference data is tenant-wide, so `referenceFetch` (`api/reference.ts`) sends no `X-Passage-LegalEntity` or `X-Passage-LegalEntity-Scope` header on any method (the service refuses writes that carry a legal-entity scope with 403 `AUTH-0003`) and adds an `Idempotency-Key` to POST. Legal-entity-scoped screens keep using `orgFetch`.

Route `/org/hierarchy` (nav "Hierarchies", duty `org.read`) is the Hierarchy designer: pick a hierarchy type, see its versions, and preview the tree as of a date with a date input and slider (`versionAsOf` over the loaded version summaries; no as-of request per move). "Show draft" previews the open draft. The displayed version is compared with its previous version (`compare?from=<versionNo>&to=<versionNo>`) and added or moved nodes carry a "changed" badge whose tooltip names the previous parent. Hierarchy reads (`api/hierarchy.ts`: types, versions, one version with nodes, compare) are tenant-level and go through `referenceFetch`, so they send no legal-entity header; org unit names come from the legal-entity context and one operating-unit list per page. The open draft is editable (`HierarchyDraftEditor.tsx`): drag a node onto a new parent, or use Move up/down, Indent, Outdent, Alt+arrow keys, the "Move under" list, the "Add org unit" picker and "Replace selected with"; "Save draft" PUTs the whole node set with the optimistic-lock `version`. "Create draft" POSTs a draft copied from the latest published version. "Publish…" POSTs `:publish` with an effective date and requires a 10 to 500 character reason when the date is in the past (the type must allow backdating; the server enforces the backdate duty and maker-checker). The UI gates writes on duties passed to `OrgLayout`: `org.hierarchy.write` shows the edit controls and Create draft (without it the draft is a read-only tree), `org.hierarchy.publish` shows Publish…, and `org.hierarchy.backdate` allows past effective dates. The server still enforces every duty, and a 403 AUTH code renders "You don't have permission to do this". `module.ts` does not pass duties yet and the shell has no source of them, so in production only the read-only tree shows until duty wiring from the shell lands (follow-up). Edit controls, dragging and Alt+arrow moves lock while a save is pending. Nodes in the previous version and gone from the displayed one are listed under "Removed since vN", and "Export CSV" downloads the displayed version.

Needs: none beyond the shell lockfile.
