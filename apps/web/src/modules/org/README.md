# org web module

Organization workspace for wave 6: legal-entity switcher (`passage.org.legalEntity`), Legal entities screen and legal-entity-scoped operating unit, site and warehouse lists. Discovered by the shell via `module.ts`.

Routes: `/org/reference-data` (nav "Reference data", duty `org.read`) holds the Reference data screen: countries, currencies, regions, languages, units and conversions, one tab loaded at a time. Deactivate, add custom unit and add conversion render only when `OrgLayout` receives `org.reference.write` in `duties`; the Test conversion panel needs no write duty.

Tenant-level fetch rule: reference data is tenant-wide, so `referenceFetch` (`api/reference.ts`) sends no `X-Passage-LegalEntity` or `X-Passage-LegalEntity-Scope` header on any method (the service refuses writes that carry a legal-entity scope with 403 `AUTH-0003`) and adds an `Idempotency-Key` to POST. Legal-entity-scoped screens keep using `orgFetch`.

Legal-entity scope contract (server, fail closed): a request with a legal entity sees that entity; a request with none sees no legal-entity-scoped rows. The `X-Passage-LegalEntity-Scope: ALL` GET only widens to every entity when the caller holds `org.switcher.all-scope`; the tenant middleware drops that duty on writes and on reads that omit `ALL`, and `dbx.WithTenantTx` maps no-entity plus the duty to `*`.

Route `/org/hierarchy` (nav "Hierarchies", duty `org.read`) is the Hierarchy designer: pick a hierarchy type, see its versions, and preview the tree as of a date with a date input and slider (`versionAsOf` over the loaded version summaries; no as-of request per move). "Show draft" previews the open draft. The displayed version is compared with its previous version (`compare?from=<versionNo>&to=<versionNo>`) and added or moved nodes carry a "changed" badge whose tooltip names the previous parent. Hierarchy reads (`api/hierarchy.ts`: types, versions, one version with nodes, compare) are tenant-level and go through `referenceFetch`, so they send no legal-entity header; org unit names come from the legal-entity context and one operating-unit list per page. The open draft is editable (`HierarchyDraftEditor.tsx`): drag a node onto a new parent, or use Move up/down, Indent, Outdent, Alt+arrow keys, the "Move under" list, the "Add org unit" picker and "Replace selected with"; "Save draft" PUTs the whole node set with the optimistic-lock `version`. "Create draft" POSTs a draft copied from the latest published version. "Publish…" POSTs `:publish` with an effective date and requires a 10 to 500 character reason when the date is in the past (the type must allow backdating; the server enforces the backdate duty and maker-checker). The UI gates writes on duties passed to `OrgLayout`: `org.hierarchy.write` shows the edit controls and Create draft (without it the draft is a read-only tree), `org.hierarchy.publish` shows Publish…, and `org.hierarchy.backdate` allows past effective dates. The server still enforces every duty, and a 403 AUTH code renders "You don't have permission to do this". `module.ts` does not pass duties yet and the shell has no source of them, so in production only the read-only tree shows until duty wiring from the shell lands (follow-up). Edit controls, dragging and Alt+arrow moves lock while a save is pending. Nodes in the previous version and gone from the displayed one are listed under "Removed since vN", and "Export CSV" downloads the displayed version.

Needs: none beyond the shell lockfile.

Operating units, sites and warehouses (`StructurePages.tsx`, writes in `api/write.ts`): the list pages have an add form and an activate/deactivate action with a confirm step. Operating-unit writes go through `referenceFetch` (no legal-entity header, `Idempotency-Key` on POST). Site and warehouse writes and their conflict re-reads go through `orgFetch` with `X-Passage-LegalEntity` set to the row's legal entity (the chosen site's for a new warehouse), because those tables are behind the legal-entity RLS policy and the service drops the all-scope duty on writes; POSTs also carry an `Idempotency-Key`. Operating units need `org.operating-unit.write`, sites and warehouses `org.site.write`. Reference-data and hierarchy writes need their route duty and `tenant.administer`, as the service requires.

PSG-640: `/org/locations` (nav "Locations", duty `org.read`) lists locations with their warehouse and type, adds a location and activates or deactivates one (`org.site.write`; every write names the warehouse's legal entity in `X-Passage-LegalEntity`). The teams screen adds team types, edits a team (name, description, effective-to) and adds, ends and removes members (`TeamWrites.tsx`; `org.operating-unit.write` plus `tenant.administer`). The fiscal calendars screen renames and activates calendars, takes the periods of a custom-pattern year as one `start end` pair per line and can regenerate an existing year with `force`. `LegalEntityProvider.reload()` refreshes the switcher after a legal entity is added or deactivated. Under the "All entities" scope the header badge reads "Viewing all entities": site, warehouse and location forms still show because each write names its own legal entity.

Currency rounding and name translations (PSG-648): the Rounding tab of `/org/reference-data` (`RoundingTab.tsx`, `api/rounding.ts`) lists, sets and removes a currency's rounding rules and tests an amount; writes go through `referenceFetch` (tenant-level, no legal-entity header) and show for `org.reference.write` with `tenant.administer`; the rule list reads through `orgFetch` under the switcher scope, because legal-entity rules are behind the legal-entity RLS policy, and a test for one legal entity is sent under that entity's `X-Passage-LegalEntity`. `/org/names` (`NameTranslationsPage.tsx`, `api/translations.ts`) maintains name translations of legal entities, operating units, sites and warehouses through the legal-entity-scoped routes; writes need the owner type's write duty and one concrete legal entity (the ALL scope is read-only), and the gateway rows for `PUT`/`DELETE …/translations/*` are a pending authz seed (see `services/org/NOT-IMPLEMENTED.md`).

PSG-6 slice 52: the Legal entities page has a Copy action per row for a caller with `org.legal-entity.write` and `tenant.administer` (`CopyLegalEntityForm.tsx`, `copyLegalEntity` in `api/structure.ts`). The form asks for the new code, name, country, accounting currency and time zone (prefilled from the source) and lets the user leave out sites and warehouses, locations (disabled without sites) and rounding rules; the result line says how many rows were created, and the switcher and table reload. `legalEntityValues.ts` holds the validation shared with the add form.
