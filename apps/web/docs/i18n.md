# Languages in the web app (#509)

Library: `react-intl` (FormatJS), pinned at 12.1.7. It gives ICU messages (plurals, selects) and the Intl formatters, and its `IntlProvider` is mounted in `main.tsx` for pages that use `FormattedMessage` or `useIntl`.

## How the shell is translated

`shell/copy.ts` stays the English source and keeps its shape, so no page changes. Its last line is `localizeCopy(english, activeLocale, ...)`:

- English is returned as it is.
- Spanish: a string is the message at the same path in `shell/i18n/es.ts`; a function is the ICU message at that path, formatted with the function's arguments (the argument names are in `shell/i18n/functionMessages.ts`). Anything missing stays English.
- Pseudo-locale `en-XA`: the English text is accented, padded by a third and put in brackets.

The language is fixed for the page. It comes from `?lang=` (used for the pseudo-locale), then the choice saved by the Language control in the help panel, then the browser language. Changing it reloads the page.

## Adding or changing a string

1. Add it to `shell/copy.ts`. If it needs an argument, write a function.
2. Add the Spanish at the same path in `shell/i18n/es.ts`. For a function, add its ICU message to `es.ts` and its English ICU form and sample arguments to `functionMessages.ts`.
3. Run `npx vitest run src/shell/i18n`. The tests check that each function's ICU message gives what the English function gives, that Spanish keeps the same placeholders, and that Spanish covers at least 95% of the strings.

Do not write user-facing text in a component. `src/shell/i18n/hardcoded.test.ts` counts text in JSX and in `aria-label`, `title`, `placeholder` and `alt` attributes per shell file and fails when a file has more than its baseline in `hardcodedBaseline.json`. Lower the baseline when you move a string out.

## Numbers, dates and money

Use `formatNumber`, `formatCurrency`, `formatPercent`, `formatQuantity`, `formatDate` and `formatDateTime` from `shell/format.ts`. They follow the active language. Do not use `toFixed`, `toLocaleString` or string concatenation for numbers shown to people. Defaults from the legal entity (its country and currency) are not applied yet; a legal entity's currency is passed to `formatCurrency` by the caller.

## Problem messages

`lookupProblem` in `shell/errors/catalog.ts` returns the entry in the active language. Translations are in `shell/i18n/problemMessages.ts`, keyed by code; the common codes (`COM-*`, `AUTH-*`, `HTTP-*`) are done and the rest show English.

## Pseudo-locale pass

`e2e/pseudo-locale.demo.spec.ts` opens the shell and the procure-to-pay and order-to-cash pages with `?lang=en-XA` against the demo build and checks that shell controls are bracketed and accented, that nothing makes the page scroll sideways, and that the help panel holds the longer text. Run it with `npx playwright test --project=demo-flows e2e/pseudo-locale`.
