# payroll

Payroll engine, wave 43 (PSG-43), slice 1.

## What it does

Slice 1 is the pure gross-to-net engine behind a stateless HTTP preview:

- Versioned US rule set `US-FED-2025.1` (`internal/domain/ruleset.go`): the 2025
  Pub 15-T Worksheet 1A annual percentage method (automated payroll systems) with the
  standard and Step 2 checkbox schedules for Single / married filing separately,
  married filing jointly and head of household; 2020+ W-4 Steps 2, 3, 4(a), 4(b) and
  4(c), and pre-2020 W-4 allowances (4,300 each). Social Security at 6.2% to the wage
  base (176,100.00), Medicare at 1.45% plus the employee-only 0.9% additional over
  200,000.00, FUTA at 0.6% to 7,000.00, Colorado flat 4.40% state income tax.
- The federal withholding line carries the schedule row it used (`bracket`), so the
  amount can be explained without re-running the engine.
- Pre-tax deductions reduce federal and state wages; a Section 125 deduction
  (`reducesFica`) also reduces FICA and FUTA wages, a 401(k) does not.
- BR-43.1 note: the PRD's federal figure (577.43) omits Worksheet 1A line 1g; the
  engine follows Pub 15-T (504.66). See `NOT-IMPLEMENTED.md`.
- Each tax is computed on the unrounded basis and rounded half-up to 0.01 per line
  (BR-43.2). Every line carries `basisAmount` and `ruleVersion`.
- Statement hash: SHA-256 over the lines (immutability check, FR-43.7).
- Supplemental withholding for off-cycle bonuses at the flat 22% rate, with the 37%
  rate above 1,000,000.00 of YTD supplemental wages (BR-43.11).
- Deduction arrears with ARREARS, NO_ARREARS and PARTIAL policies and recovery limits
  (BR-43.10, `internal/domain/arrears.go`).
- Retro delta computation (BR-43.4, `internal/domain/retro.go`): earning deltas summed
  across the affected periods into RETRO_* earnings that the current run taxes.
- Pay-run lifecycle guards (`internal/domain/run.go`): transitions and the
  calculator/finalizer separation of duties (BR-43.8).
- Run posting matrix (`internal/domain/posting.go`): `RunPosting` summarizes a run's
  statements into one balanced journal by account role (BR-43.1 GL example);
  `MapToAccounts` replaces each role with the GL account stored in the legal entity's
  posting profile and fails closed (PAY-GL-003) on a role without an account.
- Pay runs (`internal/store/runs.go`, `internal/api/runs.go`, migration 0003): create
  (calculates and stores every statement), review, finalize (the calculator cannot
  finalize, BR-43.8), post to the general ledger through `platform/go/ledgerclient`
  under the key `payroll-run:<id>`, and a GL reconciliation of the POSTED runs to the
  ledger balances. Create is idempotent per (tenant, legal entity, caller,
  Idempotency-Key), so one caller can neither read nor probe another's keys.
- Posting profile: GL accounts come only from `pay_posting_account`, written through
  `PUT /v1/payroll/posting-profiles/{legalEntityId}` under its own duty. No request
  body can carry an account (unknown fields are refused).
- Proof fixtures in `internal/domain/testdata/`, generated by an independent
  exact-fraction reference (`python3 -I gen_payroll_fixtures.py`): `payroll-us-200.csv`
  (200 Pub 15-T gross-to-net scenarios) and `payroll-retro-25.json` (25 retro cases).

Post first checks that the ledger exists and belongs to the run's legal entity (422
PAY-GL-005), then fixes the journal lines and the ledger on the run before the ledger
call. After an ambiguous outcome (transport error, timeout, 5xx, idempotency conflict)
the pin stays, so a retry resends the identical entry (a different ledgerId is 409
PAY-GL-004). After a definite refusal (a 4xx other than a conflict, e.g. an unknown,
unpostable or suspended account) the pin is cleared, so the retry uses the corrected
posting profile or ledger. A POSTED run posted again to another ledger is 409
PAY-GL-004. Reconciliation sums the stored journals of the POSTED runs on the
reconciled ledger: a later posting-profile edit changes only runs not yet posted. See
`NOT-IMPLEMENTED.md`.

## Layout

```
cmd/payroll/            entrypoint: dbx.Connect -> dbx.Migrate -> httpx.NewRouter -> Serve
internal/domain/        pure rules, tax functions, statement calculation (no I/O)
internal/api/           HTTP handlers and DTOs
internal/store/         pay run, posting profile and GL reconciliation persistence
migrations/             NNNN_*.sql applied by dbx.Migrate (infrastructure, pay runs, posting profile)
api/openapi.yaml        OpenAPI 3.1 for every endpoint
events/asyncapi.yaml    AsyncAPI 3 (no events are published yet)
charts/payroll/         Helm chart
```

## Run

```
PASSAGE_ENV=dev SERVICE_NAME=payroll DATABASE_URL=postgres://... \
  HTTP_ADDR=:8080 go run ./cmd/payroll
```

## Test

```
go vet ./... && go test ./...
```

Domain tests are pure. API and store tests use `platform/go/testkit` and are skipped
unless `PASSAGE_TEST_DATABASE_URL` is set.

## Endpoints

| Method | Path                         | Duty                  |
|--------|------------------------------|-----------------------|
| POST   | /v1/payroll/calculations     | payroll.run.maintain  |
| POST   | /v1/payroll/runs             | payroll.run.maintain (Idempotency-Key required) |
| POST   | /v1/payroll/runs/{id}/review | payroll.run.maintain  |
| POST   | /v1/payroll/runs/{id}/finalize | payroll.run.finalize |
| POST   | /v1/payroll/runs/{id}/post   | payroll.run.post      |
| GET    | /v1/payroll/runs/{id}        | payroll.run.read      |
| GET    | /v1/payroll/gl-reconciliation | payroll.run.read     |
| PUT    | /v1/payroll/posting-profiles/{legalEntityId} | payroll.posting-profile.maintain |
| GET    | /v1/payroll/posting-profiles/{legalEntityId} | payroll.run.read |
| GET    | /healthz, /readyz            | public                |

Posting needs `LEDGER_URL` and the service identity key (see the chart values); without
them post and reconciliation answer 503 PAY-GL-002.

## Error codes

Problem details use `type: https://passage.dev/problems/<code>`.

| Code         | HTTP | Meaning                                                              |
|--------------|------|----------------------------------------------------------------------|
| COM-0001     | 400  | Request failed validation (bad decimal, unknown field, bad enum)      |
| AUTH-0001    | 401  | Unauthenticated                                                       |
| AUTH-0003    | 403  | Missing duty                                                          |
| PAY-RULE-001 | 422  | No published rule set, schedule or state rate covers the inputs        |
| PAY-RULE-002 | 422  | Rule-set publisher must differ from its author (domain, not yet wired)|
| PAY-RUN-004  | 422  | The user who calculated a run cannot finalize it (domain)             |
| PAY-RUN-005  | 422  | Illegal pay-run state transition (domain)                             |
| PAY-RUN-006  | 422  | Input the engine refuses (pre-tax above gross, payDate before periodStart) |
| PAY-RUN-007  | 404  | Pay run not found                                                     |
| PAY-RUN-008  | 409  | Idempotency-Key reused with a different request                       |
| PAY-RUN-009  | 503  | Pay runs not configured                                               |
| PAY-GL-001   | 502  | The general ledger refused or did not answer                          |
| PAY-GL-002   | 503  | No general ledger configured                                          |
| PAY-GL-003   | 422  | The posting profile has no GL account for a payroll role              |
| PAY-GL-004   | 409  | The run is already fixed or posted against another ledger             |
| PAY-GL-005   | 422  | The ledger is unknown or belongs to another legal entity              |
| COM-0500     | 500  | Unexpected failure                                                    |

for property tests). No new third-party dependencies.
