# Not implemented in PSG-14 slice A

Slice A ships period control, the allocation, year-end and checklist engines, the `:check` endpoint and the service skeleton. Slice B of the same ticket carries the rest; no other ticket owns it.

| Deliverable or AC | Status | Reason |
|---|---|---|
| AC1 / Deliverable 1: period control enforced at the posting API | partial | decision logic, `FOR SHARE` read, `:check` and the resolver ship, and `internal/api/period_contract_test.go` proves through the real routes that a closed period rejects (check) or reports closed (resolve) for every source system the ledger, payables, receiving, assets, eam and production send, and that only the closed module and unmapped sources are rejected when one module is closed. The ledger-side half (`services/ledger/internal/store/closed_period_test.go`) proves its own posting paths reject; a single test that drives a ledger posting into a closed close-service period needs the ledger and close in one harness (ledger code is out of this lane). Maintain, hold, close and reopen endpoints, the Temporal reopen workflow with expiry and the status-changed publisher are slice B |
| AC2 / Deliverable 3: allocation engine | partial | fixed, basis and reciprocal computation ship with fixtures; allocation rule persistence, run, post and reversal API are slice B and need the ledger |
| AC3 / Deliverable 5: year-end close | built | `POST /v1/close/year-end-runs` stores the run (`year_end_run`), posts the closing and opening entries to the ledger and emits `dev.passage.close.yearend.completed.v1`; idempotent per ledger and fiscal year. Open: the trial balance is supplied by the caller (close does not read ledger balances yet); the ledger line has no dimension field, so dimensions travel as line text and entries for one account under several dimensions post as separate lines; a closing entry refused by a closed ledger period needs the period reopened first (`ledger.period.postclosed` is not requested) |
