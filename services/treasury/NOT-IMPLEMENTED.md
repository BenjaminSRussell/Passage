# NOT-IMPLEMENTED (treasury, PSG-36)

Slice 1 builds: bank accounts with the Draft -> Active -> Inactive -> Closed
lifecycle (FR-36.1, partial), camt.053 statement import with duplicate and
sequence-gap detection (FR-36.2, partial), the cash forecast over stored entries
(FR-36.9, partial), the pure matching-score engine (FR-36.3 scoring, BR-36.1,
BR-36.2; domain only), the `statement.imported.v1` event, and the web module
`apps/web/src/modules/treasury` (bank accounts list, create and detail;
statement import and detail; cash forecast with entry form).

Slice 2 (PSG-3602) is a completeness pass over this file against PRD 7.36:
it adds the PRD sections (parameters, documents, batch jobs, duties and SoD,
migration, performance, localization, coverage closure, operations) that the
slice 1 table did not cover. No code changed.

Slice 3 (PSG-3603) builds: check management (FR-36.6) with gap-free numbers per
bank account (`bank_account.next_check_number`), the Created -> Printed -> Sent ->
Cleared / Voided / Stopped lifecycle, void (TRS-0414 after Cleared, BR-36.5),
reprint (AC-36.5) and the `check.voided.v1` event with a `positivePayVoid`
flag; bank facilities with import / export letters of credit and guarantees
(FR-36.7), utilization = Σ open instruments, the limit block (TRS-0415) and the
`treasury.facility.override` duty (AC-36.6), an optional linked order
reference, and close; fixed-rate loan contracts (FR-36.19) with Annuity, Linear
and Bullet schedules under ACT/360, ACT/365 and 30E/360 (BR-36.15 rounding,
AC-36.15 worked example); and the web screens for all three
(`/treasury/checks`, `/treasury/facilities`, `/treasury/loans`).

Slice 4 (PSG-3604) builds: BAI2 (`internal/domain/bai2.go`: 01/02/03/16/49/88/98/99
records, funds types 0/1/2/Z/S/V/D, 88 continuations, implied decimals per ISO 4217
minor unit, each group's as-of date) and MT940 (`internal/domain/mt940.go`: :20:,
:25:, :28C:, :60F/M:, :61: with C/D/RC/RD, entry dates across the year end and
N/F/S types, :86: structured `?nn` or free text, :62F/M:) parsers beside camt.053,
with the format detected from the content (`ParseStatements`) and wired into
`POST /statements/import`; migration `0003_statement_formats.sql` widens the
stored format to `BAI2` and `MT940` and adds an optional `statementAccount` to the
bank account (kept as a hash and its last four characters, like the IBAN) so a
file that names the account by the bank's domestic number (BAI2 03 record, MT940
:25:, camt.053 `Acct/Id/Othr/Id`) matches it instead of failing TRS-0409; parse
errors name the BAI2 / MT940 `line` or the camt.053 `entry`. The FR-36.5 close
rule (bank closing − (book + outstanding) = 0; AC-36.4 refuses 0.01 with the
difference, TRS-0410) and the BR-36.3 state machine (TRS-0436) are pure domain
rules in `internal/domain/reconcile.go`, not yet behind an endpoint. Web: the import
screen takes all three formats and explains TRS-0409; the account form takes the
statement account number and the detail shows its last four characters and each
statement's format.
