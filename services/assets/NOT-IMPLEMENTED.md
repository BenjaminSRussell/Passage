## Notes for the kernel owner (wave 0) and other waves

- Idempotency uses the `idempotency_keys` table (`dbx.IdempotencyDDL`) from
  the store, claimed at the start of the command's transaction. The kernel has
  no `httpx` idempotency middleware yet; when it lands, the store helper can
  move behind it.
- `ETag` / `If-Match` are set by the service (`"<version>"`) on assets,
  depreciation runs, capex requests and leases (`POST /v1/leases/{id}/modify`
  requires If-Match).
- `lease.remeasured` is an event the PRD table does not list; it is published
  for every modification so the ledger (lease-schedule-post, D4d) and
  analytics see each change of the liability and ROU asset.
- `depreciation.posted` carries `bookCode` in place of the PRD's
  `bookDefinitionId` until book definitions exist (D1a).
- `asset.adjusted` is an event the PRD table does not list; it is published so
  consumers see every change of a book's balances.
- `capexrequest.approved` carries the PRD fields (requestId, variantId,
  amountsByYear, programPositionId) plus legalEntityId, number, currency,
  approvedAmount, inServiceDate and profileAssumption, so budget-svc (wave 38)
  and the forecast can plan the acquisition without reading the request.
