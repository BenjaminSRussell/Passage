# Phase 6: Warehouse, Quality & Logistics (waves 31-35)

Advanced warehouse management, mobile execution, quality management, transportation and B2B/EDI/e-invoicing integration.

## Wave 31: Advanced Warehouse Management

**Phase 6 — Warehouse, Quality & Logistics**

**Goal.** Location-directed work (put-away, replenishment, wave picking, cluster/zone picking) driven by configurable rules, with license plates and work templates.

**Replaces**

- *AX / D365:* Advanced warehouse management (WHS): location directives, work templates, waves, load planning, license plates, replenishment, cycle counting
- *SAP:* EWM: storage types, put-away/removal strategies, warehouse tasks/orders, handling units, wave management, physical inventory

**Deliverable**

- Location model: zones, aisles, racks, bins with capacity/profile; license plates (LP) and nested handling units
- Rules engine: location directives (put-away/pick), work templates, wave templates, replenishment (min/max, demand, wave)
- Work execution: tasks with priorities, user assignment, exceptions, short picks
- Load planning and dock scheduling; inbound ASN-driven receiving with LPs
- Slotting analysis and warehouse KPIs
- Cross-docking (planned via cross-dock templates and opportunistic at receipt) and outbound sorting to sort positions
- Value-added services and kitting (kit-to-order / kit-to-stock) as VAS work; packaging specifications per item/customer
- Transfer-order warehouse flow with LP identity preserved across sites
- Engineered labor standards with planned-vs-actual performance per user/shift (incentive pay excluded)
- Hazardous-material profiles and storage compatibility by storage class and fire-containment section

**Proof (testable acceptance)**

- [ ] Directive fixtures: 100 inbound/outbound scenarios resolve to expected locations
- [ ] Simulation: 10k lines/day warehouse model runs with no deadlocked work and p95 task assignment < 1 s
- [ ] Capacity never exceeded per location (property test)
- [ ] Wave release creates correct work and replenishment for 500 orders

**Deploy**

Warehouse management workspace; demo warehouse re-modeled with locations and directives.

**References**

- [D365 warehouse management overview](https://learn.microsoft.com/en-us/dynamics365/supply-chain/warehousing/warehouse-management-overview)
- [SAP EWM](https://help.sap.com/docs/SAP_EWM)
- [OpenBoxes (open-source WMS)](https://docs.openboxes.com/)

## Wave 32: Mobile Warehouse Execution (Scanners, RF, Voice)

**Phase 6 — Warehouse, Quality & Logistics**

**Goal.** Warehouse workers execute all work on handheld scanners with configurable menus, barcode/RFID capture and offline tolerance.

**Replaces**

- *AX / D365:* Warehouse mobile app (D365), RF menus, mobile device steps/flows
- *SAP:* SAP EWM RF framework, ITSmobile, Fiori warehouse apps

**Deliverable**

- Mobile app (PWA + Android native shell, Zebra/Honeywell scanner integration): receive, put-away, pick, pack, move, count, inquiry
- Configurable menu/flow designer: steps, validations, scan patterns (GS1 AI parsing), error handling
- Offline queue with conflict resolution; session/device management
- Voice picking adapter and RFID (EPC) read integration points
- Label printing (ZPL) via print service
- Automation adapter for AS/RS, conveyors and sorters (MFS telegrams via the wave-25 edge gateway)
- Printer and output-queue management: device types, queue failover, document routing rules, browser printing

**Proof (testable acceptance)**

- [ ] E2E (Playwright on emulated device): full inbound-to-outbound flow using scanned GS1-128 labels
- [ ] GS1 application-identifier parser passes the GS1 test suite
- [ ] Offline: 200 queued transactions sync without loss or duplication after reconnect
- [ ] Flow designer change deploys to devices without an app release

**Deploy**

Mobile app published to the demo warehouse devices; print service live.

## Wave 33: Quality Management & Nonconformance

**Phase 6 — Warehouse, Quality & Logistics**

**Goal.** Quality orders are generated by rules at receipt, production and shipment; results drive disposition, nonconformance, corrective action and supplier scorecards.

**Replaces**

- *AX / D365:* Quality management: test groups, quality associations, quality orders, nonconformances, corrections, certificates of analysis, inventory blocking
- *SAP:* QM: inspection plans, inspection lots (QA01), results recording, usage decisions, quality notifications (QM01), CAPA, vendor evaluation

**Deliverable**

- Tests, test groups, sampling plans (AQL), quality associations (when/what triggers a quality order)
- Quality orders with results recording (variable/attribute), usage decision, automatic inventory blocking/release
- Nonconformance → correction/CAPA workflow with root cause (8D template), cost of quality
- Certificates of analysis, supplier quality scorecards, SPC charts from results
- Device/instrument calibration tracking
- Product compliance: regulated/restricted substance lists with BOM roll-up, and safety data sheets with distribution on shipment
- Incoming vendor certificates gating acceptance, and source inspection before delivery
- Physical sample management (retention samples), multiple specification sets, in-process inspection points
- Stability studies with scheduled pull points, audit management, and FMEA/control plans (AIAG-VDA)

**Proof (testable acceptance)**

- [ ] Trigger fixtures: receipts/productions generate quality orders exactly per association rules
- [ ] Inventory remains blocked until usage decision in all paths (property test over pick/ship/consume attempts)
- [ ] AQL sampling sizes match ANSI/ASQ Z1.4 tables
- [ ] CAPA workflow with effectiveness check completes (Temporal test)

**Deploy**

Quality workspace enabled for the demo plants; CoA generation on shipments.

**References**

- [AX 2012 quality management](https://learn.microsoft.com/en-us/dynamicsax-2012/appuser-itpro/about-quality-management)

## Wave 34: Transportation Management & Freight

**Phase 6 — Warehouse, Quality & Logistics**

**Goal.** Plan loads and routes, rate-shop carriers, tender, track and reconcile freight invoices against expected charges.

**Replaces**

- *AX / D365:* Transportation management (D365 TMS): rating, routing, load building, carrier tendering, freight reconciliation
- *SAP:* SAP TM: freight units, freight orders, carrier selection, freight settlement

**Deliverable**

- Load building and route planning (constraints: capacity, time windows) with OR-Tools VRP
- Rating engine: carrier rate cards, accessorials, fuel surcharges, rate shopping; tendering workflow
- Shipment tracking events (EDI 214/API), proof of delivery
- Freight reconciliation: carrier invoice vs expected charges, dispute, accrual posting
- Landed cost allocation to inventory (freight, duties) feeding costing
- Landed cost voyages with shipping containers, folios and goods-in-transit orders (estimates vs actuals)
- Yard management (transportation units, yard moves, detention) and driver check-in/out with gate log
- Dangerous-goods checks for transport (49 CFR / ADR / IMDG / IATA): segregation, ADR 1.1.3.6 points, DG shipping papers
- Own-fleet resources and driver-hours constraints in VRP; lane RFQ for strategic freight procurement; layer-based load plans
- Foreign-trade data, commercial invoice, and denied-party screening / customs filing provider hooks (providers in wave 48)

**Proof (testable acceptance)**

- [ ] VRP fixtures: solutions feasible and within 10% of best-known on Solomon benchmarks
- [ ] Rating fixtures: 200 shipments rate to expected charges
- [ ] Freight reconciliation matches/mismatches as expected; landed cost allocation sums to invoice exactly
- [ ] Tendering workflow timeouts cascade to the next carrier

**Deploy**

Transportation workspace; demo carriers and rate cards; landed cost active.

## Wave 35: B2B Integration: EDI, e-Invoicing & Integration Hub

**Phase 6 — Warehouse, Quality & Logistics**

**Goal.** Trading partners exchange orders, ASNs and invoices via EDI X12/EDIFACT and Peppol, and any external system integrates through a governed API/event hub.

**Replaces**

- *AX / D365:* AIF/data entities, EDI via partners, electronic reporting (ER) for e-invoicing, Dual-write
- *SAP:* IDocs/ALE, SAP PI/PO / Integration Suite, Document and Reporting Compliance (e-invoicing)

**Deliverable**

- EDI engine: X12 (850/855/856/810/820/214) and EDIFACT (ORDERS/DESADV/INVOIC) mapping, AS2/SFTP transport, partner profiles, acknowledgments
- e-Invoicing: Peppol access point integration (UBL 2.1), Factur-X/ZUGFeRD, country mandates framework (IT SDI, MX CFDI hooks)
- Integration hub: public REST/GraphQL APIs, webhooks, Kafka topic subscriptions, API catalog (Backstage), developer portal, keys and quotas
- iPaaS connectors: Salesforce, Shopify, Stripe reference connectors
- Message monitor with replay and partner SLAs
- Catalog punchout (cXML and SAP OCI) returning requisition lines to wave 17
- cXML document exchange with cXML networks (Ariba/Coupa): OrderRequest, confirmations, ship notices, invoices
- PLM reference connector (Teamcenter / Windchill / file drop) into engineering change requests
- Customer self-billing intake (EDIFACT INVOIC 389, VDA 4908) with line matching and dispute worklist

**Proof (testable acceptance)**

- [ ] EDI round-trip tests against a partner simulator for every supported transaction set
- [ ] Peppol UBL validates against the Peppol BIS schematron
- [ ] Webhook delivery at-least-once with retries and dead-letter; replay reproduces state
- [ ] Phase 6 exit: demo distributor partner exchanges PO → ASN → invoice via EDI with the demo manufacturer

**Deploy**

Integration hub + developer portal at developers.<env>.passage.dev; EDI engine connected to a partner simulator.
